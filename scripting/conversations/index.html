Conversations

Conversation flow is structured into Topics (similar to what the original scripts call Info).

Most of the time, a Topic is one of the selectable choices you can make when talking to an NPC, but they can also be automatically triggered (forced) or be part of sub-dialogue flow.

In general, a Topic consists of the following parts:

  • Name of the NPC the Topic belongs to
  • Conditions of when the Topic should appear
  • An Act function (coroutine) containing the actual sequence

Upon startup, the game searches for all classes inheriting from UConversationTopic and registers them to the NPCs they belong to.

Note

The conversation and quest scripts of Gothic 1 Remake were not hand-written but generated by a graphical design tool, and while we tried to make the output as readable as possible, they are not as nice to view and edit by humans.

Still, writing them by hand should feel somewhat similar to how it was done in original games scripts.

Topic conditions

Section titled “Topic conditions”

There are 3 types of conditions in each Topic:

  1. Topic flow conditions: “Have I ever done this other topic before?” - fastest to evaluate, checked first
  2. Dynamic conditions: Some often recurring dynamic conditions like “Am I close to this location”
  3. Script conditions: IsVisible script function where you can put custom script code to return true/false - slowest, checked last

Localization

Section titled “Localization”

To have the game look up a localized Text-ID, use the LocText(...) function (returns FText). Alternatively, you can assign a Text-ID directly to an FText, but that does not work in all contexts unfortunately.

Note

AngelScript does not support implicit conversion between types well when the target is a function argument. Therefore the LocText function acts as a conversion function here. operator= was overloaded to “just work” for FText.

Quests

Section titled “Quests”

Each quest is defined as a class of type UQuest. Quests must belong to a story, which can be the Gothic 1 Remake main story or your custom made one.

You can either trigger the quests manually, or have them automatically check for start, success and failure conditions every couple ticks.
